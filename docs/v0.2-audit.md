# Zeenat.js v0.1 audit for v0.2

## Scope and baseline

This audit was completed before v0.2 implementation. It covered `src/`, `tests/`,
the playground, examples, public exports, build configuration, package metadata,
SSR behavior, scheduling, reduced motion, deterministic seeding, and resource
cleanup.

The untouched v0.1 baseline passed `npm run check` on August 25, 2026:

- Prettier, ESLint, and strict TypeScript passed;
- 19 Vitest tests passed across four files;
- ESM, CJS, declarations, and sourcemaps built for all four public entries;
- 12 package export targets and SSR-safe ESM imports were verified;
- the React artifact retained its `"use client"` boundary;
- the playground production build passed.

## Review findings

| Priority | Area                 | Finding                                                                                                                                                                                                 | v0.2 action                                                                                                                                          |
| -------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| High     | Effect isolation     | `SceneEngine.startEffects()` mounts the complete preset inside one `try` block. A single third-party mount exception tears down every healthy effect.                                                   | Give each effect an owned scope, clean only that scope on failure, continue mounting siblings, and report the failure through diagnostics.           |
| High     | Resource ownership   | Scheduler tasks, animations, resize callbacks, and effect cleanup functions are stored scene-wide. This prevents precise rollback for one failed effect.                                                | Introduce effect-scoped resource registries backed by the existing scene scheduler/animation runtime. Preserve the v0.1 context methods.             |
| Medium   | Animation lifetime   | `AnimationRegistry` keeps finished finite animations in its set until scene teardown. This is bounded for built-ins, which use infinite animations, but community effects can accumulate registrations. | Remove animations on `finish`/`cancel` and expose active counts for diagnostics.                                                                     |
| Medium   | Callback isolation   | An exception in a RAF task or resize callback can prevent sibling callbacks from running; a RAF exception can also prevent the next shared frame from being scheduled.                                  | Isolate callbacks, keep the scheduler alive, and send structured errors to diagnostics without noisy default logging.                                |
| Medium   | Responsive density   | Effects read a mount-time viewport. The core publishes resize snapshots, but built-ins do not subscribe, so crossing the small-screen breakpoint does not recalculate density until restart.            | Restart effects only when the density breakpoint or relevant DPR class changes; continue publishing ordinary resize snapshots without rebuild churn. |
| Medium   | Layering             | Visual order is implicit preset array order. There is no stable distinction between ambient, background, foreground, flyover, and top-edge decoration.                                                  | Add a small semantic layer model with stable numeric slots and per-effect order while retaining array order inside a slot.                           |
| Medium   | Diagnostics          | State is available only through the controller. Active effects, nodes, animations, timers, RAF tasks, viewport, motion, failures, and seed cannot be inspected.                                         | Add opt-in diagnostics snapshots/subscriptions and a `debug` React/vanilla option. Do not render a production panel automatically.                   |
| Medium   | Preset validation    | Presets require only `id`, `name`, and a non-empty effect list. Metadata, duplicate IDs, effect option validation, and contributor tooling are absent.                                                  | Extend metadata compatibly, validate built-ins and community definitions, and add `npm run validate:preset`.                                         |
| Medium   | Tree shaking         | `sideEffects: false` and ESM entries are correct, but there is no consumer-bundle proof. `zeenat/effects` and `zeenat/presets` are aggregate artifacts only.                                            | Add individual effect/preset exports and esbuild fixtures proving exclusions, while preserving aggregate entries and string preset IDs.              |
| Low      | Long duration        | Finite `duration` is clamped to the browser maximum timeout, so a duration above roughly 24.8 days stops early. Schedule boundaries already re-arm safely.                                              | Reuse chunked timer behavior for long durations or document a deliberate maximum.                                                                    |
| Low      | Scheduler validation | Zero/invalid recurring intervals can create a hot timer loop.                                                                                                                                           | Validate scheduler delays/intervals and clamp or reject invalid values.                                                                              |
| Low      | CSP evidence         | The runtime creates no `<style>` tags, data URLs, eval calls, or CSS keyframes. It does use element style attributes and Web Animations, whose enforced-policy behavior is not tested.                  | Add an enforced CSP browser fixture and document the exact policy. Add no nonce API unless a style element becomes necessary.                        |

## Sound v0.1 decisions to preserve

- No browser globals are accessed during module evaluation.
- React server output is a stable, empty decoration root, and the package build
  preserves the Next.js client directive.
- Vanilla and React share one framework-neutral engine.
- The root and every effect layer are fixed/absolute, clipped, pointer-inert, and
  `aria-hidden`; the engine does not mutate host application nodes or global CSS.
- Manual pause and hidden-document pause are tracked separately.
- Schedule strings require an explicit UTC offset or `Z`, long schedule delays are
  chunked, and schedule timers are cleared on destroy.
- Random streams are deterministic per seed and effect index.
- Owned roots, layers, registered animations, scheduler tasks, and environment
  listeners are released on destroy; destroy is idempotent.
- Effect factories close over typed options. This produces better inference than a
  universal option bag and should remain the customization model.
- The package has zero runtime dependencies and external React peers.

## Compatibility constraints

v0.2 must preserve:

```tsx
<Zeenat preset="pakistan-defence-day" />
<Zeenat preset="us-independence-day" />
```

```ts
zeenat({ preset: "pakistan-defence-day" });
```

It must also preserve `pause`, `resume`, `restart`, `destroy`, `setIntensity`,
existing effect factory names/options, custom `defineEffect({ id, mount })` values,
and custom `definePreset({ id, name, effects })` values.

All new metadata and layering fields therefore remain optional at the type boundary,
with safe defaults matching v0.1 behavior.

## v0.2 design direction

```text
React / vanilla adapters
          │
          ▼
     SceneEngine
          │
   ┌──────┼──────── diagnostics snapshot/subscription
   │      │
effect scope per definition
   │      ├─ semantic layer slot + stable order
   │      ├─ scoped animations / timers / RAF / resize callbacks
   │      └─ abort + cleanup + failure record
   │
shared scheduler and animation runtime
```

The runtime remains synchronous for current presets. Code splitting is provided by
explicit import boundaries rather than making the existing string resolver async.
Built-in string IDs remain the convenience path and necessarily include the small
built-in registry; advanced consumers can import one preset or effect subpath.

## Testing strategy

- Unit tests remain the fastest layer for validation, scheduling, deterministic
  randomness, and state transitions.
- jsdom integration tests cover adapter ownership and failure rollback.
- Playwright covers actual layout, pointer safety, Web Animations, viewport behavior,
  repeated mount/unmount, CSP, and performance budgets.
- Deterministic visual snapshots use a fixed seed, reduced motion or paused animation
  state, fixed fonts/backgrounds, and explicit viewports.
- Consumer esbuild fixtures prove tree-shaking boundaries.
- A dependency-free Node script enforces package gzip budgets after build.

## Canvas assessment gate

The initial v0.2 effects should remain bounded DOM/SVG implementations until real
browser measurements show a clear need for canvas. Snow, petals, and leaves can stay
under restrained mobile/desktop node budgets, while DOM preserves simple styling,
individual Web Animation ownership, and static reduced-motion fallbacks. A shared
canvas renderer should be implemented only if the browser performance tests fail
those budgets or a future high-density effect requires it.
